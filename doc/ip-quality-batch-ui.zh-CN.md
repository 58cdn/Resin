# 显式节点批量任务页面

入口为节点池和手动检测页面中的「批量 IP 质量任务」，路径 `/resources/ip-quality-batch`。页面复用 [PR20 批量任务 API](ip-quality-batch-tasks.zh-CN.md)，插件仍默认关闭。打开页面不创建任务、不读取来源、不自动恢复任务。

## 提交范围与来源

1. 每行输入一个 32 位十六进制节点 Hash，最多 50 个非空行；先校验整份列表，再规范化去重。任何非法行或超过上限都会在请求前拒绝，不展开筛选器、平台、订阅或全部节点。
2. 点击「准备范围与来源」只读取来源目录。准备不逐个查询节点，不冻结出口；执行时由服务端逐节点验证存在性与出口变化。
3. 显式选择已启用、可用且无需密钥的已支持来源。没有默认选中的来源；force 默认为 false。经节点来源会请求已配置的外部目标，目标能看到节点出口 IP；页面不修改目标或启用插件。
4. 点击提交后先在本页内存中固定完整请求和随机 request_id，再发送一个 POST。提交按钮、重试及其他操作有同步防重；已提交的范围、来源和 force 不可原地修改。

`force:false` 可复用有效缓存，`force:true` 仍可能共享在途检测。目录可用不保证离线库或外部目标成功。页面不保存请求、任务结果或密钥到浏览器持久化存储。

## 丢失响应与恢复

若提交响应丢失、超时或格式不合法，任务可能已经接受。页面保留原 request_id、Hash、sources 和 force，只有点击「手动重试原提交」才重发相同请求。没有自动 POST 重试。引擎重启、配置替换、淘汰或过期会结束服务端幂等窗口，**相同请求仍可能再次执行**。

取得任务 ID 后优先通过 GET 查询该任务；任务 ID 可选中复制。在恢复区输入明确的任务 ID 并点击恢复，只读取一次，不重新提交、不读取来源目录、不立即开始轮询。恢复任务 B 会清空并隐藏先前任务 A 的提交草稿。恢复响应必须匹配请求的 taskID；本页创建的任务还必须匹配 request_id、完整节点集合、来源和 force。

任务只在当前插件引擎内存中存在，终态最长保留 15 分钟，容量淘汰可能更早。404 也可能表示旧引擎或不存在，不能证明任务从未执行。

## 观察与取消

接受任务后串行查询：上一个响应正文读取完成后再等两秒，下一次只发 GET。每轮观察最多五分钟，每次请求包含正文解析最多等待 20 秒；到期停止页面观察，不代表服务端 30 分钟任务期限结束。用户可显式继续另一轮五分钟观察，或只读取一次。

查询错误、401/403、404、429 或 503 均暂停查询并隐藏旧任务详情；页面不会自行重试。429 提示稍后手动重试。离开、清空、暂停或客户端超时会废弃旧操作和迟到响应，不发送服务端取消。

「请求服务端取消」是独立 POST，先废弃可能在途的旧 GET，避免旧响应覆盖取消结果。取消中需要后续状态确认；取消响应丢失时只提示未知，优先查询原任务。取消不回滚完成缓存，也不能证明外部请求没有发生或共享检测停止。

## 结果与验收

任务进度、节点状态和来源观测分别显示。completed 文案为「已返回结果」，另列 all_ok、partial_failure、all_failed、unavailable、no_observations；全部来源失败仍可属于执行已完成的任务。错误只作为文本渲染。

任务记录的是历史元数据，允许观测时间早于任务创建或已经过期；不据此声称当前出口、有效缓存、节点健康、账户可用或低风险。页面不展示原始 Data、配置指纹或 summary。每项提供单节点页面链接，进入后仍需用户显式读取当前缓存。

本切片增加独立模型单测与 mock 浏览器套件，覆盖整份拒绝、50 项限制前置、固定 envelope、失联重试、任务归属、迟到响应、A→B→A、取消与查询竞争、正文超时、五分钟观察期限、鉴权/限流、历史与失败语义、键盘、中文/英文和移动布局。浏览器只用合成 API、隐藏浏览器和随机回环端口，无真实节点或外部目标。新增套件加入现有串行 Linux/Windows CI，保留原三套浏览器检查。

独立审查与本地证据记录于 PR；最终合并、准确候选 CI 和实际 master CI 以 PR 描述为准。没有后台周期检测、每来源配额、风险评分、发布或生产部署。
