# 显式节点定期检测

插件和 `background_enabled` 均默认关闭。本切片支持管理员提供固定节点名单的周期检查；尚不支持整个节点池、订阅、平台或过滤结果的自动扫描。没有新 API、后台任务历史或进度恢复界面；查看结果继续使用现有只读缓存接口。

通过现有插件配置入口设置以下字段。示例只表示配置格式，必须先替换节点 Hash；本文及测试没有实际启用任何节点配置。

```json
{
  "enabled_sources": ["db-ip"],
  "background_enabled": true,
  "background_nodes": ["01000000000000000000000000000000"],
  "background_sources": ["db-ip"],
  "background_interval": "30m"
}
```

- `background_nodes` 必须有 1–50 个唯一的 32 位十六进制节点 Hash，大小写等价；没有隐式对象扩展。
- `background_sources` 必须明确选择至少一个已实现、可用且被 `enabled_sources` 启用的来源。可选适配器仍需显式目标；未知、重复、未启用和未实现的密钥来源均被拒绝。
- `background_interval` 必须为 Go duration，范围 5 分钟至 24 小时。调度关闭时可保存部分配置，但所有已提供字段仍受格式、范围和来源可用性校验。
- `db-ip` 使用现有离线库，不自动下载数据库。选择网络来源会让配置的目标看到节点出口 IP；原有 HTTPS、DNS 公网地址固定、无重定向及不带用户凭据的边界保持不变。

配置校验和 Engine 构造只准备状态。内建插件仅在启用配置成功保存后激活；首次运行等待完整间隔。每轮顺序访问名单，设置 5 分钟取消预算，每次尝试前推进游标。超时后下一轮从下一个节点继续，避免名单末尾长期饥饿。每轮完成后再等待完整间隔，不重叠、不补跑错过的周期。取消遵循现有 context 协作约定；若手动调用仍在等待同一请求，周期预算到期仅撤销本轮的等待者。

入场时跳过不存在、禁用、不健康或无公网出口的节点。状态可能在入场之后改变；此实现不承诺与节点停用原子同步。现有引擎仍在结果发布前核对节点存在性、出口 IP 和出口版本。检测使用 `force:false`，逐来源复用有效内存或持久缓存，过期后才重新执行；配置间隔不是强制刷新间隔。调度设置不改变观察指纹，调整名单或间隔不会使既有结果全部失效。手动请求、批量任务和定时检测共享既有并发限制与同对象/来源的合并请求。

重新配置会停止并等待旧 Engine，成功保存后新间隔重新计时。保存失败会恢复并激活旧配置，同样重新等待完整间隔；不恢复原计时进度、批量任务 ID 或内存任务记录。无效配置拒绝前不会停止旧配置。停用只有在保存成功后停止旧实例；保存失败保留旧实例。插件关闭或进程退出取消并等待工作。进程重启从已保存的启用配置重新等待完整间隔，不恢复游标或补发离线期间的检测。

本轮不增加 provider QPS、日配额、熔断、风险评分或生产启用。检测结果仍是带时间与来源的观察，不能推断商业服务可用性或低风险。专用拨号计数按真实节点拨号增长，离线查询和缓存命中不增加拨号次数。

验证使用 fake Host、进程内虚拟时间和受控响应：默认关闭、显式范围、保存前零检测、保存回滚、首延迟、预算与公平游标、缓存有效/过期、共享请求、停止、重配及并发 Activate/Close。Windows/Linux 最终 CI 与合并记录见本 PR；没有真实节点探测、凭据操作、发行、部署或运行服务变更。
