# 来源请求控制：默认关闭的运行接入

本切片把[独立控制核心](ip-quality-request-guards-core.zh-CN.md)接入 builtin IP 质量检测。插件仍默认关闭，`source_guards` 默认空列表，不实施请求拒绝。配置能力与离线验证完成不表示已在运行服务启用，也不表示真实供应商或节点已经验证。

控制对象只有 `egress-consistency`、`cloudflare-challenge`、`ai-region` 三个网络来源。每个来源在整个 Resin 进程内共享一个令牌桶、UTC 日软预算及保护熔断；不是每节点、每目标或供应商账号分别计数。一个异常节点或目标可以影响同来源的其他节点，因此这些策略必须显式启用，不能当作供应商停机诊断。离线 DB-IP 和未实现的密钥来源不参与；配置策略不会启用来源或自动补充目标。

## 配置和生命周期

插件配置新增 `source_guards` JSON 数组，最多三个不重复的来源。以下只展示一种策略格式，不会自动写入实际配置：

```json
{
  "source_guards": [
    {
      "source": "egress-consistency",
      "enabled": true,
      "qps": 2,
      "burst": 2,
      "daily_limit": 1000,
      "consecutive_failure_threshold": 3,
      "open_for": "30s"
    }
  ]
}
```

范围：qps 1–100、burst 1–64、daily_limit 1–1000000、连续故障阈值 1–100、open_for 1 秒至 1 小时。缺省来源或只有 source 的零策略关闭拒绝；任何非零策略即使 enabled=false 也必须完整合法。未知、重复、大小写歧义、null、错误类型及越界字段均拒绝。QPS 是令牌补充速度，burst 允许突发，不是任意滑动秒的严格上限。

controller 随 resinApp 创建一次，不随 Engine、插件实例或配置验证重建。Configure 仅准备，旧 Engine 完全停止后，在 Manager 成功保存并提交配置的 Activate 阶段才应用策略。保存阻塞/失败、禁用状态下的配置校验不会提前应用；失败回滚保留旧策略与账本。插件停用后不会发检测；重新启用、热重配或同进程 Manager 重启不会获得新预算。删除策略关闭拒绝，但不清空消耗或冷却状态。

进程重启清空此内存账本；无持久化、跨进程或账号协调。即使策略关闭，已准入尝试仍计入当日账本，曾启用的令牌桶保留速率并自然补充/扣减；首次启用可能立即遇到已用完的日预算。只有 UTC 日期向前变化才重置每日计数，时钟回拨或旧并发采样不会重复补充或缩短新冷却。

## 一次尝试和熔断反馈

每次实际来源 HTTP RoundTrip，在 URL 静态安全校验后、调用 Host.DoViaNode 之前申请许可。多目标来源逐请求计数，最多八个目标；一次 Source.Check、TCP 拨号、上游实际收到请求或供应商计费都不是此单位。预先取消不扣额；准入后即记账，后续 DNS/节点问题、取消或中性完成均不退款。内存/磁盘缓存命中和加入已有 singleflight 不增加尝试，force 只跳过缓存，不能跳过控制器。准入控制器不排队，不自动重试，也不发主动半开探针。

许可在 Host 返回响应头时完成一次，defer 中性兜底确保退出时释放半开占用：

| 结果 | 熔断反馈 |
| --- | --- |
| 请求 context 取消或截止、明确取消错误 | 中性 |
| Host 明确分类的 URL/DNS 安全拒绝、节点不可用、DNS 不可用 | 中性 |
| 未分类的其他 Host 错误 | 中性 |
| Host 明确分类的 HTTP/TLS/outbound 传输错误 | 故障 |
| 实际 HTTP 429 或 500–599 | 故障 |
| 其他有效 HTTP 响应头状态 | 成功，仅指收到响应 |
| 后续 body 读取、格式解析或质量分类 | 保留原适配器语义，不修改已完成的许可 |

管理 API 429、本地准入拒绝、实际上游 429 是不同事件。有效 challenge/blocked/risky 或出口不一致本身不说明传输失败；例如上游 429 可以同时参与本地保护并保留适配器的真实 risky 观测。403 响应头可结束连续传输故障，但不代表目标可用。没有解析 Retry-After，使用显式固定冷却。

中性既不增加故障也不清零连续故障。冷却结束后下一次原有请求可竞争唯一半开许可；成功关闭、故障重新冷却、中性释放占用但不延长原冷却。跨配置的旧结果不能改变当前代熔断，仍未结束的旧半开许可不会允许第二个试探。

## API、缓存和界面

本地抑制单独返回为 `suppressed_sources`，来源固定、计数最多八次、原因最多四类：`source_rate`、`source_daily_budget`、`source_circuit_open`、`source_half_open_busy`。每个原因带 count，可选 retry_at 是最早重新评估时间，不保证准入；未结束的半开试探没有可预知时间。无原始错误、URL、查询参数或目标地址。

**某来源任一目标被抑制，就不返回该来源本次的 SourceResult，也不写入内存或持久缓存。** 即使其他目标已发出请求并收到响应，也不把这个不完整来源推成 clear 或一致；admitted 数量明确表示可能已经执行。原缓存保持原时间和 TTL。其他来源的完整结果独立保留，并按原规则缓存和汇总。

单次 POST 仍返回 HTTP 200 表示有界检测流程给出了结果，不代表质量通过。全抑制时 sources 为 `[]`、summary 保持 unknown/null，且省略 checked_at；混合返回时 checked_at 只取真实返回来源的最大观测时间。缓存 GET 仍只返回缓存观测，不持久化或回放抑制记录，也不触发新请求。

批量项目生命周期仍可 completed，观测状态另为 suppressed 或 partial_suppression；全抑制省略 checked_at，finished_at 仅表示任务结束。单次和批量页面严格检查观测与抑制来源互斥、合起来恰好覆盖所选来源、计数和时间一致，分别展示限制原因与真实观测，不自动重试。旧缓存核对仍是独立只读操作。

策略字段不影响观测 fingerprint，单独改控制策略不会使已有真实观测失效。原有节点出口代次、取消和缓存 TTL 校验继续适用。该保护只约束 IP 检测请求，不改变节点健康、代理路由、原节点熔断或资源控制。

验证使用 fake Host、固定 HTTP 响应、注入时钟、受控回环和浏览器 fixtures；最终独立审查、准确候选与合并后 Windows/Linux CI 见 PR 描述。真实目标/节点探测、服务启用、供应商计费硬额度、密钥来源及生产部署仍不在此次执行范围。
