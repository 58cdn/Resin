# 显式节点批量检测任务 API

管理员可以显式提交一组节点 Hash 和来源，查询任务进度，或请求停止尚未开始的项目。本切片仅增加 API；现有手动检测页面仍只处理一个对象，没有批量 UI、周期调度或自动重试。插件仍默认关闭，提交不会启用插件、改变目标、读取密钥或修改节点健康、路由与熔断。

## 提交与重试

以下接口均使用现有管理员认证，并返回 `Cache-Control: no-store`。

```text
POST /api/v1/ip-checks/actions/check-batch
GET  /api/v1/ip-checks/tasks/{id}
POST /api/v1/ip-checks/tasks/{id}/actions/cancel
```

提交体示例（Hash 仅为格式示意，调用者必须明确选择实际节点）：

```json
{
  "request_id": "operator-selected-batch-1",
  "node_hashes": ["0123456789abcdef0123456789abcdef"],
  "sources": ["db-ip"],
  "force": false
}
```

- `request_id` 必填，1–64 个 ASCII 字母、数字、`-` 或 `_`；它是重试标识，不是凭据。
- `node_hashes` 必须有 1–50 项，限制先于去重。整个输入通过校验后才接收任务；Hash 规范化并去重，保留首次提交的项目顺序。不存在、无公网出口或后续出口变化的节点产生逐项错误，不会自动探测出口。
- `sources` 必须显式非空，未知名称或重复来源拒绝。不会自动扩大来源范围；已知但禁用或不可用的来源保留现有 unavailable 语义。
- `force` 缺省为 false；其他字段不得省略。字段名区分大小写，拒绝重复键、null、未知字段、Platform 或 subscription 选择器。仅支持调用者给定的 Hash，不展开订阅或平台。

新任务返回 **202** 和 `Location` 查询路径；相同 `request_id` 与相同规范化节点集合、来源集合和 force 返回 **200** 及原任务，不再排队。集合顺序不影响重试身份，首次项目顺序保持不变；同一标识对应不同范围返回 **409**。一次被拒绝的提交不会执行其中部分节点。

幂等性仅在**同一插件引擎代且记录仍保留**时有效。容量淘汰、记录过期、配置替换、禁用或进程重启后，同一标识可能重新执行。客户端丢失接受响应时，可以在已知的保留窗口内用同一请求标识和完全相同范围重试；不能将此机制当作持久化的 exactly-once 保证。请求体、HTTP 连接或客户端等待结束不撤销已接受任务。

## 容量、传输与生命周期

| 范围 | 上限或行为 |
| --- | --- |
| 单次输入 | 16 KiB；原始 Hash 数最多 50 |
| 当前引擎任务 | 最多 4 个未终结任务，包括排队、运行和取消中的任务 |
| 执行并发 | 当前引擎固定 2 个 worker，复用现有来源缓存与 singleflight |
| 任务截止 | 自接受起 30 分钟，包括排队时间 |
| 记录总数 | 活动和终态记录合计最多 32；只淘汰已终结的最旧记录 |
| 终态保留 | 最长 15 分钟；容量淘汰可能更早，不保证最低保留时长 |
| HTTP 准入 | 提交 2 次/秒、burst 2；查询 4 次/秒、burst 4；取消 2 次/秒、burst 4 |
| HTTP 响应并发 | 三类接口各自独立最多 2 个响应，槽位保留到写入结束；轮询不占取消槽位 |
| 传输 | 请求读取截止 5 秒、响应写入截止 15 秒；单响应最多 512 KiB |

限流按 API handler 实例对全部客户端共享。429 带 `Retry-After: 1`；活动任务容量满返回 503。查询应保守轮询并处理 429，不能启动无限重试。HTTP 准入和 worker 并发**不等于**每来源 QPS、日配额或熔断；这些能力仍未实现。

任务保存在内存中，绑定接受时的引擎。配置替换、禁用和进程停止会取消旧任务；worker 直接调用绑定引擎，不重新进入插件 Manager，不会把旧项目迁移到新配置。新引擎查询旧任务通常为 404；禁用或停止时为 503。404 也可能表示过期、容量淘汰或不存在，不能证明任务从未执行。

## 进度、取消与结果含义

任务状态为 `queued`、`running`、`canceling`、`completed`、`canceled`。项目状态为 `queued`、`running`、`completed`、`failed`、`canceled`；`progress` 按这些项目状态计数，`total` 为去重后的节点数。状态快照可能在返回后继续变化。

取消和领取项目在同一任务锁内协调：已排队项目转为 canceled，停止新的领取，并取消任务上下文。已领取项目在进入检测前再次检查取消；在途项目退出后任务才终结。已完成项目保持原结果。任务取消原因可能是 `requested`、`deadline` 或 `engine_stopped`。

取消不会回滚已写缓存，不能证明目标未收到请求，也不会取消仍被其他调用者等待的共享来源工作。即使接口返回取消中的状态，也必须以后续任务状态判断完成；停止查询本身不取消任务。

项目 `completed` 只表示检测返回了结果，**不表示所有来源成功或 IP 质量良好**。应结合 `observation_status` 和逐来源字段：

| observation_status | 含义 |
| --- | --- |
| `all_ok` | 所有返回来源均 OK 且 status 为 ok；不是低风险评级 |
| `partial_failure` | 部分来源成功，其余失败或不可用 |
| `all_failed` | 没有成功来源 |
| `unavailable` | 所有返回来源都不可用 |
| `no_observations` | 没有来源结果，不推导成功 |

任务只保留有界元数据：节点 Hash、状态、观测出口、时间、逐来源 OK/status、错误及到期时间；每条来源错误最多 512 字节。不会复制完整原始 Data、summary 或配置指纹。节点不存在、出口变更、容量或执行错误用固定的逐项错误码与说明表示。

元数据是任务执行记录；后来过期、节点出口变化或缓存刷新不改写它，不能当作当前节点质量。使用现有节点缓存接口核对当前仍有效的完整证据；缓存 GET 不是任务历史快照。成功任务响应不保证缓存持久化成功。`force:false` 允许复用有效缓存，`force:true` 跳过缓存但仍可能共享已有在途检测；以逐来源观测时间为准。

## 验证与范围

测试使用 synthetic Host/Source 和受控回环服务，覆盖全量拒绝、容量、幂等冲突、缓存/force、来源全部失败、节点变更、共享检测取消隔离、快照复制、淘汰/TTL、鉴权、慢请求体、响应槽位以及 Manager disable/configure/Stop。Go 虚拟时钟测试推进实际 30 分钟期限，验证运行中与排队任务截止、已完成结果保持以及停止后不再调用来源；不是实际等待 30 分钟。

受影响包 race、最终独立审查、最终 PR CI 与合并后的 master CI 证据以该 PR 描述及[路线图](ip-quality-roadmap.zh-CN.md)为准。测试成功不表示真实节点或外部供应商可用，更不表示生产部署。真实探测仍需明确选择有权使用的节点与目标；目标可能看到节点出口 IP。
