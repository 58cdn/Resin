# 来源 HTTP 尝试控制器：独立核心

本文记录 `internal/ipcheck/requestguard` 的独立核心契约。PR24 最初仅提供离线控制器，没有生产调用；后续[默认关闭的运行接入](ip-quality-request-guards.zh-CN.md)另行连接插件配置、检测路径、API 和 WebUI。核心本身不进行 I/O，不代表已在运行服务启用。

控制器只接受三个固定的网络来源标识：`egress-consistency`、`cloudflare-challenge`、`ai-region`。离线 `db-ip`、未实现的密钥来源、任意 URL/IP/节点标识都不在其键空间中。一次许可表示本机准入的一次 HTTP 尝试，不等于一次 `Source.Check`、一次拨号、供应商收到的请求或计费数量。一个来源可以向多个目标发请求，接入必须逐请求申请许可。

`Policy` 的零值默认关闭；非零策略必须完整满足以下范围，即使 `Enabled` 为 false 也会验证已有参数。这里是内部 Go 类型；插件 JSON 配置另见运行接入说明。

| 字段 | 含义与范围 |
| --- | --- |
| `Enabled` | 是否实施拒绝；默认 false |
| `QPS` | 令牌补充速度，每秒 1–100 个尝试许可 |
| `Burst` | 桶容量 1–64；因此不是每个滑动秒都严格至多 QPS 次 |
| `DailyLimit` | 本进程每个 UTC 日 1–1000000 次准入的软预算 |
| `ConsecutiveFailureThreshold` | 连续明确故障 1–100 次后打开熔断 |
| `OpenFor` | 打开后的冷却期，1 秒至 1 小时 |

`New` 创建独立的进程寿命对象，可注入时钟用于确定性测试；没有 ticker、网络、数据库或全局单例。宿主必须在进程范围保留这个对象，不能随 Engine、插件启停或配置校验临时重建。进程重启会清空状态，也没有多实例协调，因此该预算不能充当供应商账号的持久硬额度。

`Apply` 先验证完整策略，再提交单来源变更。非法配置不会部分改变状态。首次启用时桶可填满一次；后续配置变更只能按旧速率自然补充并按新容量裁剪，不因修改参数或关闭再打开而补满。已消耗的每日额度不会因配置变化清空。禁用时请求可继续准入，但日账本仍累计，曾启用的桶仍按保留的速率补充并扣减允许的尝试；重新启用可能立即达到今日预算。只有 UTC 日期向前变化才重置每日计数。每个来源将状态时间钳制为已观察的最高时间，回拨或较旧并发采样不能赠送额度、重复补充令牌或缩短新冷却；真实时钟追上之前可能延长等待。

`Admit` 不排队、不等待，也不发请求。准入前已取消的 context 不消耗额度。成功准入后即保守记入预算；随后取消、返回中性结果或重复完成都不会退款。拒绝使用有限原因：速率限制、每日预算、熔断打开、已有半开试探；可返回有界的 `RetryAt`，其含义是最早可重新评估的时间，不保证届时必定准入。未知来源和非法配置与这些运行拒绝分开报告。

许可的 `Finish` 最多生效一次。调用者只能提交明确成功、明确故障或中性结果；控制器不推断 HTTP、DNS、节点、风险或供应商语义。成功可结束本代的连续故障，故障可打开熔断，中性不增加故障也不把故障计数清零。打开后只允许一个受控半开试探。策略或熔断代次变更后，旧完成不能关闭新熔断；未结束试探仍须释放自己的占用，避免跨配置同时放行多个半开试探或留下永久忙锁。

接入必须定义有限、类型化的 HTTP/传输结果：管理 API 429、本地拒绝、上游 429 是三种不同事件。节点消失、DNS 安全拒绝和用户取消不能误计为供应商故障。实际收到的 HTTP 429 可以参与自我保护，同时仍保留其真实观测含义；challenge、blocked、risky 或出口不一致本身不说明传输失败。

本地抑制不能经过 `failure → stamp → cache Save` 路径。它没有新的观测时间，不得覆盖已有缓存、影响健康或路由，也不能把多目标部分执行误作全部 clear/一致。单次与批量 API、严格前端解析器和展示必须一起更新；`force` 只能跳过缓存，不能绕过控制器，共享请求也不能按等待者数量扣额。

核心测试只使用注入时钟、屏障和并发调用，不需要真实节点、外部目标、凭据或运行服务。独立审查、测试及 Windows/Linux CI 记录见各 PR；运行接入与核心分别记录，核心通过不代替接入验收。
